# Anettrace v0.8.2

## 主要变化

- 支持 ICMP/ICMPv6 联合抓取：精简模式显示收发节点，详细模式展示可用协议栈阶段；保留 ICMP 类型、代码和 Echo 标识，不将 ICMP 误关联到 TCP/UDP 连接或正在执行的收发调用。
- 在 Perfetto 的 socket 下新增 `TX packets`、`RX packets` 和未知方向轨道。选中概览节点后，可通过 **Preceding Flows** 或 `[` 跳转到实际执行线程中的原始事件。
- 原生导出在有界窗口内等待稍晚到达的 socket 归属证据；未知或冲突归属保留原始线程事件，避免根据软中断线程或相同五元组猜测所属应用。
- 修正导出过程中轨道数组扩容后父轨道引用失效的问题，并让链路 SQL 排除 socket 概览副本，避免重复统计同一观测事件。
- 补充 ICMP 抓取、socket 概览和收发链路使用说明，以及 Linux 内核集成和原生导出回归检查。

## 快速使用

```sh
# 在已有 root 权限的设备 shell 中运行；另一个终端发起 ping
./anettrace --capture-trace --proto icmp --duration 10 \
  --output /data/local/tmp/icmp.pftrace

# 应用收发与系统调度联合抓取，将 UID 替换为目标应用实际值
./anettrace --capture-trace --uid 10187 --trace-profile sched \
  --duration 20 --output /data/local/tmp/network.pftrace
```

Socket 概览节点表示已采集的包处理阶段，不等于线上包数，也不额外累加流量。
ICMP 使用 UID/PID 过滤时，缺少匹配 socket 归属证据的包会被过滤；需要观察双向
ICMP 时使用协议或地址过滤。`--traffic` 仍仅支持 TCP/UDP。

新增采集能力需要重新抓取；已有 JSONL 可以重新转换以更新显示方式，但无法补回
原始数据中没有的观测证据。下载后请核对 `SHA256SUMS` 并运行 `--version` 确认版本。
