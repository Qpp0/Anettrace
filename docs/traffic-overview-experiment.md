# 交互式流量概览

自 v0.8.4 起，Pre.5 的流量界面合入正式版，通过 `--traffic-ui` 显式启用。
`--traffic` 默认保留旧界面的逐周期追加表格；两种模式的统计口径和过滤参数相同。
`--traffic-ui` 已包含 `--traffic`，也可以同时指定两者。

## 使用

```shell
sudo ./anettrace --traffic-ui --proto tcp --uid 1000 --interval 1
```

启用 `--traffic-ui` 后，在支持 ANSI 的终端中，界面原地刷新；手机竖屏使用紧凑的多行列表，宽屏使用表格。

- 默认显示线程与端点明细：TID、线程名称、PID、协议、本地与远端 IP/端口。
  按 `p` 查看进程汇总，按 `f` 返回线程明细。
- IPv6 地址和端口完整换行显示；按 `j` 向下滚动一条、`k` 向上滚动一条，查看屏幕外的记录。
  切换视图时返回列表开头；列表按当前速率动态排序。
- 按 `q` 或 Ctrl-C 结束；与 `--capture-trace` 联用时正常停止并保存轨迹。
- RX 为接收、TX 为发送，`/s` 是相邻采样间的平均速率，累计值是本次采集的字节数。
- 默认每秒采样和刷新一次；`--interval N` 指定刷新间隔（1 至 3600 秒），速率按实际经过时间计算。
- 顶部将“当前速率”和“本次累计”分组；明细使用“累计接收 / 累计发送”，并将带 `/s` 的速率单独标注。
  顶部累计是整个采集会话的总量。交互界面的线程/端点累计保留已经采到的记录，
  同一完整身份的内核记录重建后继续累加；无法恢复采样间被淘汰且未曾观察到的数据。
- 单位自动使用 B、KiB、MiB、GiB；列表优先显示当前速率较高的条目。
- 已采到的线程/端点和进程记录在本次采集内保留，停止收发后不再因空闲 10 秒被隐藏。
  有收发时显示“活跃”，没有新增时显示空闲时长；内核明细不再可读时保留旧信息，
  标为“旧记录”，当前速率显示未知。
- 顶部每次刷新显示本地日期和时间；每条记录标出最近收发的本地时间。
  复用轨迹输出的时区转换，支持 Android 无 libc 时区数据时的系统时区回退。
- `j/k` 将列表中的目标记录移到顶部后，按 `h` 查看这条记录最近 60 次采样的历史收发量。
  每次显示采样结束时间、实际间隔、新增接收/发送字节及对应速率；采样缺失标为未知。
  默认每秒采样时约为最近一分钟，其他间隔按最近 60 次采样计算，不是固定 60 秒。
  历史中 `k` 看更早、`j` 看较新、`h` 返回列表；`p/f` 退出历史并切换视图。
  历史选中完整记录身份，不随实时列表排序改变；过去逐次数据滚动覆盖，累计记录仍保留。
- 底部显示记录范围、未显示条数、Socket 统计口径和中文快捷键提示；手机窄屏分行，
  并预留完整底部提示所需的高度。终端太小时提示放大终端。
- 实时列表按当前速率排序；判断线程网络活动时按 TID 和端点识别记录。
  需要无限期逐次追加输出时直接使用 `--traffic`，也可重定向到文件或使用 `TERM=dumb`；该模式保留原有五分钟
  空闲内核记录清理与逐周期输出，不使用交互回看缓存。
- `--count` 仍限制周期报告次数，切换视图不会增加报告次数。
- 将输出重定向到文件或设置 `TERM=dumb` 时保留原有逐次输出的九列表格及 KB 单位。

## 统计口径与容量

统计成功的 TCP/UDP sendmsg/recvmsg 返回字节数。应用层协议头、TLS 记录开销以及
MSG_PEEK 重复读取计入这些返回值；它不是网络接口的线上字节数，不能直接当作运营商计费流量。
回环通信若同时采集发送方与接收方，两个方向都能被观察到。

总累计使用独立计数器；进程累计以 PID 和进程启动时间区分，避免 PID 复用时合并旧进程。
内核进程明细最多保留 4096 个进程实例，内核 flow LRU 最多保留 16384 条。
交互界面的用户态缓存独立保留最多 4096 个进程实例及 16384 个完整线程/端点身份，
每条保留 60 次采样；达到上限时优先保留旧记录，新身份不再加入并明确提示。
完整身份包含进程启动时间，避免 PID 复用混入旧进程；不同端点分别统计。
缓存仅保存实际采到的数据，明细之和不一定等于总累计，记录也不表示 socket 仍保持连接。
首次采样前已被内核淘汰的流量无法还原；明细读取缺失或同一代计数回退时，
保留已知累计，并将受影响的逐次收发量标为未知。

进程或 flow 明细达到容量时会提示，独立总累计继续工作；若 inflight 记录丢失，
总累计也可能不完整。UDP 端点无法确定时保留字节数并显示未知端点。
采样读取失败时提示明细不完整，并避免把缺失期间的历史累计误算为瞬时突增。
速率按实际采样时间计算，而非假设调度总能严格按 `--interval` 执行。

`--pid` 仍按线程 TID 过滤，`--uid` 和 `--proto` 的范围不变；进程汇总只包含过滤后采到的流量。
线程名称取自 I/O 操作时的内核 `comm`，最多 15 字节；界面保留采集到的完整名称，
内核字段以外的长线程名无法从本次采样恢复。本地/远端是 socket 的端点：TX 为本地发送至远端，
RX 为远端接收至本地。收、发若由不同线程执行，会分别显示各自的 TID 和名称。
