# 流量概览实验版

实验分支 `codex/experiment-traffic-overview` 基于正式版 v0.8.2。构建版本号仍为
0.8.2，通过 `anettrace --version` 的 commit 与 CI 构建记录确认实验产物身份。
正式 Release 的二进制不包含本页描述的新界面。

## 使用

```shell
sudo ./anettrace --traffic --proto tcp --uid 1000 --interval 1
```

在支持 ANSI 的终端中，界面原地刷新；手机竖屏使用紧凑的多行列表，宽屏使用表格。

- 默认按进程显示，按 `f` 查看线程与端点明细，按 `p` 返回进程汇总。
- 按 `q` 或 Ctrl-C 结束；与 `--capture-trace` 联用时正常停止并保存轨迹。
- RX 为接收、TX 为发送，`/s` 是相邻采样间的平均速率，累计值是本次采集的字节数。
- 单位自动使用 B、KiB、MiB、GiB；列表优先显示当前速率较高的条目。
- 空闲条目保留 10 秒，速率归零后再隐藏；隐藏条目不会清除总累计。
- `--count` 仍限制周期报告次数，切换视图不会增加报告次数。
- 将输出重定向到文件或设置 `TERM=dumb` 时保留原有逐次输出的九列表格及 KB 单位。

## 统计口径与容量

统计成功的 TCP/UDP sendmsg/recvmsg 返回字节数。应用层协议头、TLS 记录开销以及
MSG_PEEK 重复读取计入这些返回值；它不是网络接口的线上字节数，不能直接当作运营商计费流量。
回环通信若同时采集发送方与接收方，两个方向都能被观察到。

总累计使用独立计数器；进程累计以 PID 和进程启动时间区分，避免 PID 复用时合并旧进程。
进程明细最多保留 4096 个进程实例；flow 明细最多保留 16384 条，长时间空闲或容量压力下
可能淘汰。flow 行显示当前保留记录的累计值，因此它们的和不一定等于总累计。
界面的 recent flows 表示近期有活动的线程/端点记录数，不代表当前仍然连接的 socket 数。

进程或 flow 明细达到容量时会提示，独立总累计继续工作；若 inflight 记录丢失，
总累计也可能不完整。UDP 端点无法确定时保留字节数并显示未知端点。
采样读取失败时提示明细不完整，并避免把缺失期间的历史累计误算为瞬时突增。
速率按实际采样时间计算，而非假设调度总能严格按 `--interval` 执行。

`--pid` 仍按线程 TID 过滤，`--uid` 和 `--proto` 的范围不变；进程汇总只包含过滤后采到的流量。
